# Контрольна точка PLAN-GATE

- Дата: 2026-10-05
- Об'єкт перевірки: декомпозиція SRS на 31 тікет, залежності, календарний план, реєстр ризиків
- Рішення: **GO** — виконання тікетів реалізації розблоковано

## Критерії та результат

| # | Критерій | Результат |
|---|---|---|
| 1 | Декомпозиція покриває затверджені вимоги | ✅ Усі 55 вимог SRS мають відповідні тікети; покриття зафіксовано в `spec/traceability.md` |
| 2 | Кожен тікет має джерело в специфікації | ✅ Тікетів без ID вимоги немає |
| 3 | План не містить функціональності поза SRS | ✅ Єдина нова ідея (видалення профілю) винесена в Addendum FEI-30, а не в Feature |
| 4 | Залежності логічно узгоджені | ✅ Кожен Feature блокується своїм Test; цикли відсутні |
| 5 | Gate розташовані перед критичними переходами | ✅ PLAN → DATA → ANALYTICS → RELEASE; Gate не виробляють код і тести |
| 6 | Ролі розподілені | ✅ Validation і рішення Gate за людиною; Test, Feature і чернетки документації — за агентом |
| 7 | Суттєві ризики мають конкретні заходи | ✅ 15 ризиків у `docs/risks.md`, з них 8 — специфічні для роботи агента |
| 8 | Вимоги з вищою ціною відмови посилено контролюються | ✅ Точність сум, ізоляція профілів, перенесення в «Інше», межі періодів — окремі Verification і умови Gate |

## Зауваження, враховані перед рішенням

1. Тип тікета для ВП-01 змінено з Feature на Addendum.
2. Вимоги процесу (TDD, журнали) не стали окремими тікетами, а перевіряються на кожному Gate.
3. Jira не дозволила створити власні типи тікетів: тип SDD фіксується міткою та описом.

## Наслідки рішення GO

Розблоковано тікети FEI-3 і далі. Наступна контрольна точка — DATA-GATE (FEI-14) після
завершення ядра даних і перевірки ізоляції профілів.
