# Сесія агента 02 — декомпозиція SRS на тікети

- Дата: 2026-10-05
- Агент: Claude Code
- Вхід: `spec/srs.tex` (базова версія 1.0), `spec/traceability.md`, `spec/scenarios/expenses.feature`

## Запит людини

> Візьми затверджену SRS і розклади її на тікети. Джерелом планування мають бути ID вимог.
> Нової функціональності, якої немає у специфікації, не створюй. Запропонуй типи тікетів,
> залежності, виконавців і орієнтовні тривалості.

## Що зробив агент

- Згрупував 55 вимог у 31 тікет восьми типів SDD (Specification, Addendum, Test, Feature,
  Verification, Validation, Documentation, Gate).
- Для кожного тікета вказав джерело — конкретні ID вимог.
- Побудував залежності: кожен Feature блокується своїм Test, Gate стоять перед переходами
  між етапами.
- Запропонував розподіл ролей і тривалості в днях.
- Порахував розклад, критичний шлях і окремо час людських дій.

## Перевірка людиною

| Що перевірялося | Результат |
|---|---|
| Чи має кожен тікет джерело в SRS | Так; тікетів без джерела немає |
| Чи не з'явилася нова функціональність | Ні; весь обсяг покривається наявними вимогами |
| Порядок «тест перед кодом» | Дотримано, відповідає REQ-NF-001 і REQ-NF-004 |
| Чи не виробляють Gate код або тести | Ні; Gate лише дозволяють або забороняють перехід |
| Ролі | Validation і Gate залишено за людиною, агенту не делеговано |

## Корективи людини

1. ВП-01 оформлено тікетом типу **Addendum**, а не Feature: це нова вимога, якої немає в базовій SRS.
2. Вимоги процесу REQ-NF-001, 002, 004, 006, 007 не стали окремими тікетами — вони перевіряються
   на кожному Gate за історією Git.
3. Через обмеження безкоштовного простору Jira власні типи тікетів створити не вдалося:
   тип SDD зафіксовано в мітках і описі кожного тікета.

## Результат

31 тікет імпортовано в Jira (простір Food Expenses IS, ключі FEI-1…FEI-31) разом із
зв'язками «blocks / is blocked by». План і реєстр ризиків — у `docs/plan.md` і `docs/risks.md`.
