# Аудит оформлення коду за конвенцією

Кроки 1–2 лабораторної роботи №6. Конвенція: `docs/coding-convention.md`,
машинне втілення — `ruff.toml`. Інструмент: `ruff` 0.16.9.

Виконав: Майстренко Ілля, група КН-32. Дата: 16.11.2026.

## Що перевірялося

```
ruff check .                              # відповідність конвенції
ruff format --diff .                      # обсяг майбутнього переформатування
python tools/check_reformat_safety.py     # чи змінює переформатування код
python -m pytest -q                       # повний набір тестів
python tools/check_contract.py            # відповідність контракту
```

Обсяг: 60 файлів `.py`, 6382 рядки в `src/`, `tests/`, `tools/` і
`run_server.py`.

## Перший прогін

Конвенцію вперше застосовано до коду, який до цього перевірявся лише типовим
набором правил `ruff` (`E4`, `E7`, `E9`, `F`) — а він не містить ні перевірки
docstring-ів, ні іменування, ні порядку імпортів. Тому перший прогін дав
велику кількість зауважень, і це очікувано.

| Правило | Кількість | Суть |
|---|---|---|
| D202 | 275 | порожній рядок після docstring-а функції |
| D102 | 25 | метод без docstring-а |
| D107 | 23 | `__init__` без docstring-а |
| B008 | 22 | виклик функції у значенні параметра за замовчуванням |
| D103 | 15 | функція без docstring-а |
| N818 | 12 | клас-виняток без суфікса `Error` |
| D101 | 10 | клас без docstring-а |
| N815 | 6 | змінна класу в mixedCase |
| D205 | 2 | немає порожнього рядка після першого рядка docstring-а |
| UP035, D209, F401, N802, RUF100 | по 1 | застарілий імпорт, лапки, невикористаний імпорт, ім'я методу, зайва директива `noqa` |
| **Разом** | **395** | |

Правило `E501` (довгий рядок) не дало жодного зауваження при межі 100
символів. Перед прогоном я порахував довжини рядків командою `awk` і отримав
значення до 158 — тобто нібито грубі порушення. Розбіжність виявилася в
одиницях вимірювання: `awk` рахує байти, а кириличний символ у UTF-8 займає
два байти. `ruff` рахує символи. Конвенція тепер прямо вказує, що межа — 100
**символів**, щоб ця плутанина не повторилася.

## Усвідомлені відхилення

41 зауваження з 395 стосуються місць, де конвенцію застосовувати не слід.
Кожне відхилення оголошене в `ruff.toml` з коментарем-обґрунтуванням, а не
проігноровано на місці директивою `noqa`.

| Правило | Кількість | Обґрунтування |
|---|---|---|
| B008 | 22 | `Depends()`, `Path()`, `Query()` у значенні за замовчуванням — спосіб оголошення залежностей, передбачений самим FastAPI |
| N818 | 12 | ім'я класу-винятку дослівно відповідає коду помилки контракту: `ProfileNotFound` ↔ `PROFILE_NOT_FOUND`. Суфікс `Error` розірвав би цей зв'язок |
| N815 | 6 | `unitPrice`, `occurredAt`, `categoryId` — імена полів із схем OpenAPI, затверджених на API-GATE; перейменування змінило б зовнішній інтерфейс |
| N802 | 1 | `formatTime` перевизначає метод `logging.Formatter` стандартної бібліотеки |

Після оголошення відхилень залишилося 354 зауваження.

Окремий випадок — `RUF100` у `logging_setup.py`: директива `# noqa: A003`
посилалася на правило з набору `flake8-builtins`, який конвенція не включає.
Директива була мертвою і її прибрано. Це і є призначення правила `RUF100` —
знаходити подавлення, які нічого не подавляють.

## Автоматичні виправлення

```
ruff check --fix .
Found 355 errors (280 fixed, 75 remaining)
```

Виправлено автоматично: 275 випадків D202, по одному UP035 (`Iterator`
переїхав з `typing` до `collections.abc`), D209, F401, RUF100 і одне
зауваження, що проявилося після прибирання порожніх рядків.

Усі ці виправлення торкаються лише пробілів, порожніх рядків і одного
імпорту, який ніде не використовувався. Поведінка не змінюється.

Дві правки D205 зроблені вручну: модульні docstring-и маршрутів покупок і
підсумків починалися з переліку операцій замість короткого першого рядка.
Додано перший рядок із призначенням модуля.

## Переформатування

`ruff format` змінив би 20 файлів з 60. Переформатування стосується
переважно зворотного склеювання сигнатур, які раніше були розбиті під межу
88 символів, а при межі 100 вміщаються в один рядок.

Крок 2 завдання дозволяє автоматичне переформатування лише за умови, що воно
не змінює зовнішню поведінку. Прогін тестів після переформатування цю умову
підтверджує, але не доводить: тест перевіряє те, що перевіряє, і може не
зачепити змінений рядок. Тому перед застосуванням форматування написано
`tools/check_reformat_safety.py`: він розбирає кожен файл до й після
форматування і порівнює абстрактні синтаксичні дерева з відкинутими номерами
рядків.

```
python tools/check_reformat_safety.py
Перевірено файлів: 60
Форматування змінило б: 20
Дерева розбору збігаються в усіх файлах: переформатування змінює
лише пробіли, переноси й лапки.
```

Збіг дерев розбору означає, що виконуваний код той самий, і зміни поведінки
не може бути за побудовою — це сильніше твердження, ніж успішний прогін
тестів. Після цього форматування застосовано:

```
ruff format .
20 files reformatted, 53 files left unchanged
```

| Перевірка | Результат |
|---|---|
| Дерева розбору до/після форматування | збігаються в усіх 60 файлах |
| `python -m pytest -q` | 162 passed |
| `python tools/check_contract.py` | 22 операції в контракті, 22 реалізовано, розбіжностей немає |

Жоден тест не правився. Контракт `spec/api/openapi.yaml` не змінювався.

## Що залишилося

73 зауваження, усі одного роду: публічний елемент без docstring-а.

| Правило | Кількість |
|---|---|
| D102 — метод | 25 |
| D107 — `__init__` | 23 |
| D103 — функція | 15 |
| D101 — клас | 10 |

Автоматично це не виправляється: docstring має містити зміст, а не заглушку.
Робота переходить на крок 4 — етап docstring-ів.

## Висновок

Конвенція обрана на основі офіційних документів мови, а не придумана під
наявний код: 395 зауважень при першому прогоні це підтверджують. Усі
відхилення від неї оголошені в конфігурації з обґрунтуванням, причому
більшість — 41 з 41 — зумовлені затвердженим контрактом API або вимогами
сторонніх бібліотек, а не зручністю.

Автоматичні виправлення й переформатування застосовані з доказом
незмінності поведінки сильнішим за прогін тестів. Решта зауважень не
замовчується, а має явний план закриття.
