# DATA-GATE — ядро даних готове

Контрольна точка етапу 1 плану `docs/plan.md` (тікет FEI-14). Перевіряє, що
профілі, категорії, покупки та перевірка даних реалізовані за SRS і за
затвердженим контрактом.

## Умови проходження

1. Кожна вимога REQ-F-001..REQ-F-025 має щонайменше один автоматизований тест
   із зазначеним ID вимоги (REQ-NF-002).
2. Повний набір тестів проходить однією командою без помилок (REQ-NF-003).
3. Для кожної вимоги в історії Git коміт `test:` передує коміту `feat:`
   (REQ-NF-004).
4. Усі відповіді звірено зі схемами затвердженого контракту.
5. Ізоляція даних між профілями перевірена окремо (REQ-F-003, тікет FEI-13).
6. Точність грошових обчислень перевірена окремо (REQ-F-006, REQ-NF-010).
7. Відхилений запит не створює й не змінює записів (REQ-F-019).
8. Жодної операції поза контрактом не додано.
9. Усі дії системи записуються в журнал; журнал помилок окремий (REQ-NF-008).

## Перевірка

| Умова | Результат |
|---|---|
| 1. Покриття REQ-F-001..025 | виконано; жодної вимоги без тесту |
| 2. Прогін однією командою | `python tools/run_tests.py` — 99 тестів, усі успішні |
| 3. Порядок комітів | виконано: `test:` → `feat:` для профілів, категорій, покупок і перевірки даних |
| 4. Звіряння з контрактом | виконано через `tests/contract.py`; схеми беруться з `spec/api/openapi.yaml` |
| 5. Ізоляція профілів (FEI-13) | виконано: покупки, категорії та читання за чужим ID перевірені окремими тестами |
| 6. Точність сум (FEI-21 частково) | виконано: 10 тестів обчислень, зокрема `33,33 × 3 = 99,99` і `0,05 × 0,5 = 0,03` |
| 7. Відхилений запит не змінює дані | виконано: кожен негативний тест перевіряє стан після відмови |
| 8. Немає операцій поза контрактом | виконано: застосунок віддає рівно ті шляхи, що в контракті |
| 9. Журнали | виконано: `app.log` з усіма діями, `errors.log` лише з помилками |

## Відкриті питання, які переходять далі

| ID | Питання | Стан |
|---|---|---|
| ВП-01 | Чи потрібне видалення профілю разом із даними | з ЛР2, не закрите; операції немає в контракті, тому в ЛР5 не реалізується |
| ВП-02 | Контракт не описує тіла відповіді для непередбаченої помилки сервера | відкрите; такі помилки лише пишуться в журнал |

## Вимоги поза обсягом ЛР5

REQ-I-001, REQ-I-002, REQ-I-004, REQ-NF-012, REQ-NF-014 належать до інтерфейсу
користувача. Завдання ЛР5 — серверна реалізація REST API, тому ці вимоги
свідомо не реалізуються і позначені в матриці простежуваності як такі, що
виходять за межі роботи.
