# Теги документації програмного коду

Документ описує систему теглів, якою документується код проєкту «Облік витрат
на харчування»: які теги вживаються, що кожен означає, коли обов'язковий і як
виглядає в дійсному коді.

Стиль: Google Python Style Guide, розділ 3.8, у варіанті, який розбирає
розширення `sphinx.ext.napoleon`. Мова тексту — українська, як і вся інша
документація проєкту.

Перевіряється: `ruff` з набором правил `D` (`pydocstyle`, конвенція
`google`) — наявність і оформлення; `tools/check_docstrings.py` — повнота
секцій. Конфігурація: `ruff.toml`, розділ `[lint.pydocstyle]`.

Версія: 1.0. Автор: Майстренко Ілля, група КН-32. Дата: 16.11.2026.

## 1. Загальна будова

```python
def calculate_amount(unit_price: Decimal, quantity: Decimal) -> Decimal:
    """Вартість покупки: ціна за одиницю, помножена на кількість.

    Заокруглення математичне — половина копійки йде вгору (REQ-F-006).
    Банківське заокруглення (`round` у Python) дало б інший результат:
    0,05 × 0,5 = 0,02 замість 0,03.

    Args:
        unit_price: Ціна за одиницю, перевірена `validate_unit_price`.
        quantity: Кількість, перевірена `validate_quantity`.

    Returns:
        Вартість покупки, заокруглена до копійки.
    """
```

Порядок частин незмінний:

1. **Перший рядок** — одне речення в наказовій або описовій формі, з великої
   літери, з крапкою. Поміщається в один рядок.
2. **Порожній рядок**, якщо далі є ще щось.
3. **Розширений опис** — чому саме так, які обмеження, посилання на вимогу.
4. **Секції** `Args`, `Returns`, `Yields`, `Raises`, `Attributes`, `Note`,
   `Example` — у цьому порядку.
5. **Лапки, що закривають**, на окремому рядку, якщо docstring
   багаторядковий.

Порожній рядок після docstring-а перед тілом функції не ставиться (правило
D202).

## 2. Перелік теглів

| Тег | Коли обов'язковий | Що містить |
|---|---|---|
| перший рядок | завжди | призначення елемента одним реченням |
| `Args:` | якщо є параметри, крім `self` | по рядку на параметр: ім'я, двокрапка, опис з великої літери |
| `Returns:` | якщо результат не `None` | що саме повертається; для складених типів — зі складом |
| `Yields:` | для генераторів і контекстних менеджерів | що видається в тілі `with` або циклу |
| `Raises:` | якщо функція свідомо збуджує виняток | ім'я класу винятку, двокрапка, умова, за якої він виникає |
| `Attributes:` | для класів із полями, які читаються ззовні | по рядку на поле |
| `Note:` | за потреби | істотне обмеження або пастка, яку інакше не видно |
| `Example:` | за потреби | короткий приклад виклику в блоці з відступом |

Тип параметра в дужках після імені (`unit_price (Decimal):`) **не
дублюється**: тип уже заданий анотацією в сигнатурі, і два джерела правди
розходяться при першій же правці.

## 3. Власне правило проєкту: посилання на вимогу

Де елемент реалізує конкретну вимогу специфікації, у тексті docstring-а
стоїть її ID у круглих дужках: `(REQ-F-006)`, `(REQ-A-005)`,
`(ADD-01, REQ-A-001)`.

Це не декоративне посилання. Воно замикає ланцюг простежуваності з боку коду:
матриця `spec/traceability.md` веде від вимоги до модуля, а ID у docstring-у
веде назад — від рядка коду до вимоги, яка його зумовила. Інструмент
`tools/check_docs.py` перевіряє, що кожен згаданий ID існує в SRS або
адендумі.

Форма посилання:

| Запис | Значення |
|---|---|
| `(REQ-F-006)` | елемент реалізує цю вимогу |
| `(REQ-F-026..REQ-F-029)` | діапазон вимог |
| `(ADD-01, REQ-A-001)` | вимога з адендуму, з назвою адендуму |
| `(REQ-F-031 проти REQ-F-033)` | місце, де вимоги тлумачилися спільно |

## 4. Модуль

Docstring модуля — перший рядок у файлі, до імпортів. Описує відповідальність
модуля, а не перелічує його вміст: перелік дасть автодокументатор.

```python
"""Грошові суми та кількості (REQ-F-006, REQ-F-017, REQ-F-018, REQ-NF-010).

Усі обчислення виконуються в `Decimal`. Числа з рухомою комою не
використовуються ніде: саме вони втрачають копійки на кшталт
0,1 + 0,2 = 0,30000000000000004.
"""
```

## 5. Клас

```python
@dataclass(frozen=True)
class BudgetState:
    """Бюджет разом із фактичними витратами за місяць (REQ-A-004).

    Залишок і перевищення не зберігаються в базі, а обчислюються при
    кожному читанні: інакше вони розійшлися б із покупками після
    редагування або видалення покупки (REQ-F-009).

    Attributes:
        budget: Сам бюджет із місячним лімітом.
        spent: Фактичні витрати за категорією за обраний місяць.
    """
```

Для класів-винятків `Attributes` не наводиться — склад полів однаковий для
всієї ієрархії й описаний у базовому класі `DomainError`.

## 6. Метод `__init__`

Описує, які залежності об'єкт отримує, а не повторює «створює екземпляр».

```python
def __init__(self, connection: sqlite3.Connection) -> None:
    """Прив'язує репозиторій до з'єднання з базою.

    Args:
        connection: Відкрите з'єднання; транзакціями керує той, хто
            викликає, а не репозиторій.
    """
```

## 7. Контекстний менеджер

```python
@contextmanager
def transaction(self) -> Iterator[sqlite3.Connection]:
    """Відкриває транзакцію й закриває її за результатом блоку.

    Yields:
        З'єднання всередині транзакції.

    Raises:
        sqlite3.Error: Помилка бази; транзакцію відкочено.
```

## 8. Стала модуля

Стала документується коментарем `#:` безпосередньо перед нею — цю форму
`sphinx.ext.autodoc` підхоплює як опис значення:

```python
#: Крок заокруглення грошової суми — одна копійка.
CENT = Decimal("0.01")
```

## 9. Чого в docstring-ах немає

| Не пишемо | Чому |
|---|---|
| переказ коду: «повертає список покупок» над `list_purchases` | інформації не додає; правило відсіяло близько третини чернеток |
| типи в дужках після імені параметра | дублює анотацію; два джерела правди розходяться |
| `Args` для `self` | не є параметром виклику |
| docstring у тестах | тест описує себе іменем і маркером `@pytest.mark.requirement`; у `ruff.toml` для `tests/` вимкнено `D100`–`D104` |
| історія змін, імена авторів, дати | це дає Git, а в коді вони застарівають мовчки |
| опис внутрішніх функцій з `_` на початку | за потреби коментар, але правила `D` їх не вимагають |

## 9а. Два винятки з правила про секції

**Обробники маршрутів у `api/routers/`.** Секції `Args` і `Returns` для них не
вимагаються. Їхні параметри та відповіді задані затвердженим контрактом
`spec/api/openapi.yaml`: переписати їх у docstring означало б завести друге
джерело правди, яке розійдеться з контрактом при першій же правці.

Натомість діє інша, сильніша вимога: docstring обробника **має назвати
операцію контракту**, яку він реалізує, у зворотних лапках —
``` `createPurchase` ```. Назва перевіряється проти самого контракту
інструментом `tools/check_docstrings.py`: якщо операцію перейменують або
приберуть з контракту, перевірка впаде. Це обмін слабкої перевірки на сильну,
а не послаблення.

**Конструктор, що лише передає виклик далі.** Якщо тіло `__init__` — це рівно
один виклик `super().__init__(...)` і більше нічого, docstring не вимагається:
такий конструктор нічого не додає до батьківського. Саме так оголошені
підкласи помилок у `errors.py`, кожен з яких лише задає типове повідомлення; це
повідомлення наведене в docstring-у класу.

## 10. Приклад повного набору секцій

```python
def resolve(kind: str, anchor: date, start: date | None, end: date | None) -> Period:
    """Перетворює назву періоду й опорну дату на межі періоду.

    Тиждень рахується з понеділка по неділю (REQ-F-027), місяць — з 1-го
    по останнє число (REQ-F-028), діапазон включає обидві межі
    (REQ-F-029).

    Args:
        kind: Одне зі значень `day`, `week`, `month`, `range`.
        anchor: Дата, до якої прив'язується період.
        start: Початок діапазону; потрібен лише для `range`.
        end: Кінець діапазону; потрібен лише для `range`.

    Returns:
        Період із заповненими межами включно.

    Raises:
        InvalidPeriod: Невідома назва періоду, або для `range` не задано
            межі, або кінець діапазону раніший за початок.

    Example:
        >>> resolve("week", date(2026, 11, 18), None, None).start
        datetime.date(2026, 11, 16)
    """
```

## 11. Перевірка

```
ruff check --select D .                   # наявність і оформлення
python tools/check_docstrings.py          # повнота секцій
python tools/check_docs.py                # ID вимог у посиланнях існують
```

Перші дві команди входять до повного прогону `ruff check .`; третя — окрема,
бо звіряє docstring-и з артефактами специфікації, а не з правилами стилю.
