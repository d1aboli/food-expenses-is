## Критичний шлях

Критичний шлях — ланцюг задач із нульовим запасом; затримка будь-якої з них зсуває дату завершення:

```
S-01 → G-01 → T-01 → T-02 → T-03 → T-04 → T-06 → T-08 → T-10 → G-02 → T-12 → T-13 → T-16 → G-03 → T-21 → T-22 → T-24 → T-25 → G-04
```

Довжина критичного шляху — 20.5 робочих днів, це вся тривалість проєкту. На ньому лежать усі чотири Gate, обидва ланцюги «тест → код» ядра даних і підсумків, а також валідація BDD-сценаріїв.

Поза критичним шляхом із найбільшим запасом: тести категорій і покупок (можна починати раніше), перевірки швидкодії та точності, експорт CSV, адендум ВП-01.

## Оцінка тривалості людських дій

| Показник | Днів |
|---|---|
| Повна тривалість проєкту | 20.5 |
| Роботи, які виконує агент | 23.5 |
| Рішення й перевірки людини | 5.5 |
| З них на критичному шляху | 3.0 |

Технічні операції агент виконує швидко, але кожен Gate, валідація та перевірки вимагають людини. 3.0 дня людських дій лежать безпосередньо на критичному шляху, тому саме доступність людини, а не швидкість агента, обмежує пропускну здатність. Практичний висновок: Gate планувати на початок дня і не накопичувати по кілька перевірок підряд, інакше кожен день очікування додається до строку один в один.
